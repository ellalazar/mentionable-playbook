# Playbook 11 — Writing a GEO-optimized article

> **Slash command**: [`/mentionable-article`](../.claude/commands/mentionable-article.md)
> **Who it's for**: SEO content, writers, coaches / consultants who produce their own content
> **Deliverable**: `projects/<projectSlug>/articles/<slug>/` — article.md + jsonld.json + sources.json + meta.json

## Why

Writing an article *that ranks on Google* is no longer enough. LLMs (ChatGPT, Perplexity, Claude, Gemini) select and cite pages according to measurable criteria — and those criteria were quantified by the Princeton study **"GEO: Generative Engine Optimization"** (Aggarwal et al., KDD 2024).

This command systematically applies the 4 highest-lift tactics:

| Tactic | Measured lift | How it's applied here |
|---|---|---|
| Cite_Sources | +30-40 % | ≥ 1 outbound link per 300-400 words to authority sources |
| Quotation_Addition | +25-35 % | ≥ 2 direct quotes attributed by name |
| Statistics_Addition | +25-30 % | ≥ 5 sourced numeric statistics |
| Fluency_Optimization | +15-25 % | Short sentences, active voice, precise vocabulary |

As a bonus, the article includes:
- **TL;DR / Key takeaway in 5 bullets** at the top (LLMs often extract the first standalone summary)
- **Structured FAQ** (matches People Also Ask + LLM fan-outs)
- **JSON-LD** (`Article` + `FAQPage` + `BreadcrumbList`) ready to embed
- **Audit trail** of the fetched sources (`sources.json`)

## Prerequisites

1. **Read `CLAUDE.md`** at the repo root. It's the anti-AI-detection style guide (no em-dashes, banned vocabulary, patterns to avoid). The command enforces it in step 0, and a final BLOCKING check prevents writing the article if a rule is violated.
2. Node ≥ 18 (`node --version`).
2. **Optional**: a brief generated by [`/mentionable-brief`](../.claude/commands/mentionable-brief.md) or a plan generated by [`/mentionable-pillar`](../.claude/commands/mentionable-pillar.md). Otherwise the command can start from a free-form topic.
3. **First run**: you'll be prompted to enter your author info (`name`, `url`, `jobTitle`, `organization`) → stored in `author.json` at the root (gitignored). Reused for all subsequent articles.
4. Web access for `WebFetch` (authority sources are fetched in parallel to extract real stats/quotes).

## How to use

### From an existing brief

```
/mentionable-article articles/cnv/brief.md
```

### From a pillar/satellite plan

```
/mentionable-article pillars/communication-non-violente
```

The agent asks which one to write (pillar or satellite #N).

### From a free-form topic

```
/mentionable-article formation communication non violente
```

The agent suggests generating a structured brief first, otherwise starts from a minimal outline.

### Via Cursor / Claude Desktop / other

Copy the prompt from [`.claude/commands/mentionable-article.md`](../.claude/commands/mentionable-article.md), replace `$ARGUMENTS` with your input.

## Pipeline in 8 steps

1. **Input resolution** — detects whether `$ARGUMENTS` is a .md path, a plan folder, or a free-form topic.
2. **Author** — reads `author.json` or creates the file interactively.
3. **Fetch authority sources** — 3 to 5 `WebFetch` calls in parallel to extract real stats / quotes / facts (anti-hallucination).
4. **Plan & length** — adapted to intent: pillar 3k-6k words, satellite 1.2k-2.5k words.
5. **One-shot writing** — applies the 4 Princeton tactics to each H2.
6. **JSON-LD** — Article + FAQPage (if FAQ) + BreadcrumbList (if pillar/satellite).
7. **sources.json + meta.json** — audit trail + usable metadata.
8. **Quality summary** — counts of outbound links, quotes, stats vs Princeton targets.

## Output

```
projects/<projectSlug>/articles/<slug>/
├── article.md       # YAML frontmatter + markdown body
├── jsonld.json      # @graph schema.org (Article, FAQPage, BreadcrumbList)
├── sources.json     # audit trail of the fetched URLs
└── meta.json        # title, slug, wordCount, h2Count, faqCount, etc.
```

The `article.md` contains a **YAML frontmatter** (title, description, slug, date, author, keywords, wordCount) directly consumable by Astro, Hugo, Next.js, Gatsby, Jekyll, etc.

## Anti-hallucination

The Princeton study shows that the **citation lift comes from real facts**, not from text volume. So:

- **Stats**: come from `WebFetch` or from verifiable knowledge (Wikipedia, institutional sources).
- **Quotes**: verbatim from the source. If there's no access to the exact text → paraphrase **without quotation marks**.
- **When in doubt**: a `[à vérifier]` marker is left for the human.

The `sources.json` lets you check afterward which URLs were used (editorial audit).


## Variants

- **Comparison article**: if the brief's intent is `comparatif`, the agent adds a structured comparison table (often heavily cited by LLMs).
- **Transactional article** (product page, pricing page): the Princeton grid applies less; use sparingly on this type of content.
- **Multi-turn writing**: the command is one-shot, but you can rerun manually by asking the agent to rework it H2 by H2 after reading.
- **Updating an existing article**: for a refresh, run the command with `projects/<projectSlug>/articles/<slug>/article.md` as input; the agent asks whether you want to overwrite or suffix `-v2`.

## Costs

- **Claude model**: a 3000-word article = ~50-80k output tokens, ~30-50k input tokens with the WebFetch calls.
- **WebFetch**: 3-5 calls per article, included in Claude Code.
- No third-party API cost (no DataForSEO, no Gemini for this command).
